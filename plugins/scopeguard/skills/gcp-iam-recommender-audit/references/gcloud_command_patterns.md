# Pre-Validated `gcloud` Command Patterns & Mandatory 4-Step Plan

All `gcloud` commands referenced or generated by `gcp-iam-recommender-audit` have been validated at the leaf-command level via `gcloud help <leaf_command>`.

---

## 1. Mandatory 4-Step `gcloud` Plan Template

Whenever proposing or executing `gcloud` commands with this skill, include this 4-step plan in your response:

- **Step 1**: Syntax Validation via `gcloud help <leaf_command>`
  - Leaf commands: `projects get-iam-policy`, `projects set-iam-policy`, `projects add-iam-policy-binding`, `projects remove-iam-policy-binding`, `recommender recommendations list`, `recommender recommendations describe`, `recommender insights list`, `iam roles list`, `iam roles describe`, `iam roles create`, `iam list-testable-permissions`, `iam service-accounts list`, `iam service-accounts disable`, `iam service-accounts enable`, `iam service-accounts delete`, `iam service-accounts undelete`, `logging read`.
- **Step 2**: Parameter Verification
  - Always include `--project=<PROJECT_ID>` and `--quiet`.
  - Include data reduction flags (`--format`, `--limit`, or `--filter`) on all `list` commands.
  - Note: `--dry-run` and `--validate-only` are not supported on `gcloud iam roles create`, `gcloud projects *-iam-policy-binding`, `gcloud projects set-iam-policy`, or `gcloud iam service-accounts *`.
- **Step 3**: Dry-Run Command Proposal
  - Offline validation is performed via `iam list-testable-permissions` and local generation of `custom-roles/personas/*.yaml`, `custom-roles/capabilities/*.yaml`, `custom-roles/bundles.yaml`, `principal_mapping.json`, and `rollback_runbook.sh` prior to any cloud mutation.
  - Generated scripts (`rollback_runbook.sh`, `remediation_commands.sh`) print commands only (dry-run) unless `--apply` is passed, and perform an IAM policy `etag` preflight before mutating.
- **Step 4**: Command Proposal & Authorization
  - Any IAM policy, custom role, or service account modification is on the **Prohibited Operations** denylist. Autonomous execution is forbidden; always present the mutation commands and wait for explicit user authorization.

## 2. Validated Command Reference

### A. Read-Only Discovery Commands
```bash
gcloud projects get-iam-policy PROJECT_ID --project=PROJECT_ID --format=json --quiet
```
```bash
gcloud recommender recommendations list --project=PROJECT_ID --location=global --recommender=google.iam.policy.Recommender --format=json --quiet
```
```bash
gcloud recommender insights list --project=PROJECT_ID --location=global --insight-type=google.iam.policy.Insight --format=json --quiet
```
```bash
gcloud recommender insights list --project=PROJECT_ID --location=global --insight-type=google.iam.serviceAccount.Insight --limit=100 --format=json --quiet
```
```bash
gcloud recommender insights list --project=PROJECT_ID --location=global --insight-type=google.iam.policy.LateralMovementInsight --limit=100 --format=json --quiet
```
```bash
gcloud iam service-accounts list --project=PROJECT_ID --format="json(email,displayName,disabled,uniqueId)" --limit=200 --quiet
```
```bash
gcloud iam roles list --project=PROJECT_ID --format="json(name,title,description,stage,deleted)" --limit=200 --quiet
```
```bash
gcloud iam list-testable-permissions //cloudresourcemanager.googleapis.com/projects/PROJECT_ID --project=PROJECT_ID --format="json(name,customRolesSupportLevel,stage)" --quiet
```

### B. Remediation Commands (Require Explicit User Authorization)
- **Create Custom Role from YAML**:
  ```bash
  # e.g. ROLE_ID=sg_persona_<workload>, file custom-roles/personas/sg_persona_<workload>.yaml
  gcloud iam roles create ROLE_ID --project=PROJECT_ID --file=custom-roles/personas/ROLE_ID.yaml --quiet
  ```
- **Add IAM Policy Binding**:
  ```bash
  gcloud projects add-iam-policy-binding PROJECT_ID --member="PRINCIPAL" --role="projects/PROJECT_ID/roles/ROLE_ID" --project=PROJECT_ID --quiet
  ```
- **Remove Unconditional IAM Policy Binding**:
  ```bash
  gcloud projects remove-iam-policy-binding PROJECT_ID --member="PRINCIPAL" --role="ROLE_NAME" --project=PROJECT_ID --quiet
  ```
- **Remove Conditional IAM Policy Binding**:
  ```bash
  gcloud projects remove-iam-policy-binding PROJECT_ID --member="PRINCIPAL" --role="ROLE_NAME" --condition=^:^title=CONDITION_TITLE:expression=CONDITION_EXPRESSION --project=PROJECT_ID --quiet
  ```
- **Disable Inactive Service Account (Quarantine Phase)**:
  ```bash
  gcloud iam service-accounts disable SA_EMAIL --project=PROJECT_ID --quiet
  ```
- **Delete Service Account (Post-Quarantine Phase)**:
  ```bash
  gcloud iam service-accounts delete SA_EMAIL --project=PROJECT_ID --quiet
  ```

### C. Emergency Rollback Commands (Require Explicit User Authorization)
- **Re-Enable Disabled Service Account**:
  ```bash
  gcloud iam service-accounts enable SA_EMAIL --project=PROJECT_ID --quiet
  ```
- **Undelete Deleted Service Account (Requires 21-Digit `uniqueId`, within 30 Days)**:
  ```bash
  gcloud iam service-accounts undelete SA_UNIQUE_ID --project=PROJECT_ID --quiet
  ```
- **Full Project IAM Policy Restore from Snapshot**:
  ```bash
  gcloud projects set-iam-policy PROJECT_ID PATH_TO_IAM_POLICY_BACKUP_JSON --project=PROJECT_ID --quiet
  ```
