# Pre-Validated `gcloud` / `bq` Patterns, Terraform HCL & Output Templates

All CLI commands and Infrastructure-as-Code (IaC) templates generated by `gcp-iam-role-architect` follow these standardized, pre-validated patterns.

---

## 1. Mandatory 4-Step `gcloud` Validation Plan

Whenever proposing or executing `gcloud` or `bq` commands with this skill, include this 4-step plan in your response:

- **Step 1**: Syntax Validation via `gcloud help <leaf_command>`
  - Validated leaf commands: `iam roles list`, `iam roles describe`, `iam roles create`, `iam roles update`, `iam roles delete`, `iam roles undelete`, `iam list-testable-permissions`, `projects get-iam-policy`, `projects add-iam-policy-binding`, `projects remove-iam-policy-binding`, `storage buckets add-iam-policy-binding`, `storage buckets remove-iam-policy-binding`, `secrets add-iam-policy-binding`, `secrets remove-iam-policy-binding`, `pubsub topics add-iam-policy-binding`, `pubsub subscriptions add-iam-policy-binding`, `run services add-iam-policy-binding`, `artifacts repositories add-iam-policy-binding`, `kms keys add-iam-policy-binding`, `iam service-accounts add-iam-policy-binding`, and `bq show --format=prettyjson` / `bq update --source`.
- **Step 2**: Parameter Verification
  - Always include `--project=<PROJECT_ID>` and `--quiet`.
  - Include data reduction flags (`--format`, `--limit`, `--filter`) on all `list` commands.
  - Note: `--dry-run` is not supported on `gcloud iam roles create` or `*-iam-policy-binding` commands; offline validation is performed via `iam list-testable-permissions` and local artifact generation first.
- **Step 3**: Dry-Run Command Proposal
  - Generate `role_design_report.md`, `custom-roles/personas/*.yaml` (plus any delta `custom-roles/capabilities/*.yaml`), `provision_roles_and_bindings.sh`, `main.tf`, and `rollback_runbook.sh` in the output directory prior to any cloud mutation.
- **Step 4**: Command Proposal & Authorization
  - Creating custom roles or modifying IAM policy bindings is on the **Prohibited Operations** denylist for autonomous execution. Always present the generated commands/Terraform and wait for explicit human approval.

## 2. Resource-Scoped CLI Binding Commands (`provision_roles_and_bindings.sh`)

### A. Create or Update Custom Role from YAML
File slug == role ID. Persona roles use `ROLE_ID=sg_persona_<workload>` (title `SG Persona · <Workload>`) under `custom-roles/personas/`; delta capability roles use `ROLE_ID=sg_cap_<domain>_<access>[_<qualifier>]` (title `SG Capability · <X>`) under `custom-roles/capabilities/`. The `sg_` prefix follows `--role-prefix` > `$SCOPEGUARD_ROLE_PREFIX` > `sg_`.
```bash
gcloud iam roles create ROLE_ID \
    --project=PROJECT_ID \
    --file=custom-roles/personas/ROLE_ID.yaml \
    --quiet
```

### B. Bind at the Exact Resource Scope

- **Project Scope** (e.g., `bigquery.jobs.create`):
  ```bash
  gcloud projects add-iam-policy-binding PROJECT_ID \
      --member="PRINCIPAL" \
      --role="projects/PROJECT_ID/roles/ROLE_ID" \
      --project=PROJECT_ID \
      --quiet
  ```

- **BigQuery Dataset Scope** (e.g., `bigquery.tables.getData`, `bigquery.datasets.get`):
  ```bash
  # Snapshot current dataset metadata & ACLs first:
  bq --project_id=PROJECT_ID show --format=prettyjson PROJECT_ID:DATASET_ID > dataset_acl_backup_DATASET_ID.json
  # Add dataset-level IAM binding via Python/jq update on access[] array and apply:
  bq --project_id=PROJECT_ID update --source dataset_acl_updated_DATASET_ID.json PROJECT_ID:DATASET_ID
  ```

- **BigQuery Table Scope**:
  ```bash
  bq --project_id=PROJECT_ID add-iam-policy-binding \
      --member="PRINCIPAL" \
      --role="projects/PROJECT_ID/roles/ROLE_ID" \
      PROJECT_ID:DATASET_ID.TABLE_ID
  ```

- **Cloud Storage Bucket Scope**:
  ```bash
  gcloud storage buckets add-iam-policy-binding gs://BUCKET_NAME \
      --member="PRINCIPAL" \
      --role="projects/PROJECT_ID/roles/ROLE_ID" \
      --project=PROJECT_ID \
      --quiet
  ```

- **Secret Manager Secret Scope**:
  ```bash
  gcloud secrets add-iam-policy-binding SECRET_ID \
      --member="PRINCIPAL" \
      --role="projects/PROJECT_ID/roles/ROLE_ID" \
      --project=PROJECT_ID \
      --quiet
  ```

- **Pub/Sub Topic / Subscription Scope**:
  ```bash
  gcloud pubsub topics add-iam-policy-binding TOPIC_ID \
      --member="PRINCIPAL" \
      --role="projects/PROJECT_ID/roles/ROLE_ID" \
      --project=PROJECT_ID \
      --quiet

  gcloud pubsub subscriptions add-iam-policy-binding SUBSCRIPTION_ID \
      --member="PRINCIPAL" \
      --role="projects/PROJECT_ID/roles/ROLE_ID" \
      --project=PROJECT_ID \
      --quiet
  ```

- **Cloud Run Service Scope**:
  ```bash
  gcloud run services add-iam-policy-binding SERVICE_NAME \
      --region=REGION \
      --member="PRINCIPAL" \
      --role="projects/PROJECT_ID/roles/ROLE_ID" \
      --project=PROJECT_ID \
      --quiet
  ```

- **Artifact Registry Repository Scope**:
  ```bash
  gcloud artifacts repositories add-iam-policy-binding REPOSITORY_ID \
      --location=LOCATION \
      --member="PRINCIPAL" \
      --role="projects/PROJECT_ID/roles/ROLE_ID" \
      --project=PROJECT_ID \
      --quiet
  ```

- **Cloud KMS CryptoKey Scope**:
  ```bash
  gcloud kms keys add-iam-policy-binding KEY_NAME \
      --keyring=KEYRING_NAME \
      --location=LOCATION \
      --member="PRINCIPAL" \
      --role="projects/PROJECT_ID/roles/ROLE_ID" \
      --project=PROJECT_ID \
      --quiet
  ```

- **Service Account Resource Scope** (for `iam.serviceAccounts.actAs` / `getAccessToken`):
  ```bash
  gcloud iam service-accounts add-iam-policy-binding TARGET_SA_EMAIL \
      --member="PRINCIPAL" \
      --role="projects/PROJECT_ID/roles/ROLE_ID" \
      --project=PROJECT_ID \
      --quiet
  ```

## 3. Terraform HCL Template (`main.tf`)

```hcl
# ==============================================================================
# Generated by gcp-iam-role-architect
# Requirement: <REQUIREMENT_SUMMARY>
# ==============================================================================

variable "project_id" {
  description = "Target Google Cloud Project ID"
  type        = string
  default     = "<PROJECT_ID>"
}

variable "principal_member" {
  description = "IAM principal in type:identifier format (e.g., user:alice@example.com or serviceAccount:sa@proj.iam.gserviceaccount.com)"
  type        = string
  default     = "<PRINCIPAL>"
}

# 1. Project-Level Custom Role(s)
resource "google_project_iam_custom_role" "<ROLE_TF_NAME>" {
  project     = var.project_id
  role_id     = "<ROLE_ID>"    # e.g. sg_persona_<workload>
  title       = "<ROLE_TITLE>" # e.g. SG Persona · <Workload>
  description = "<ROLE_DESCRIPTION>"
  stage       = "GA"
  permissions = [
    # <INCLUDED_PERMISSIONS>
  ]
}

# 2. Resource-Scoped IAM Binding(s)
# Example A: Project-level binding (only for project-scoped permissions like bigquery.jobs.create)
resource "google_project_iam_member" "<BINDING_TF_NAME>" {
  project = var.project_id
  role    = google_project_iam_custom_role.<ROLE_TF_NAME>.name
  member  = var.principal_member
}

# Example B: BigQuery Dataset-level binding (for dataset-scoped permissions like bigquery.tables.getData)
resource "google_bigquery_dataset_iam_member" "<DATASET_BINDING_TF_NAME>" {
  project    = var.project_id
  dataset_id = "<DATASET_ID>"
  role       = google_project_iam_custom_role.<DATASET_ROLE_TF_NAME>.name
  member     = var.principal_member
}
```
